# kernel — 清单（内核）

**内核。** 它不是「一堆通用组件」，而是**三层**：

```
主题层（长相）  ×  母版层（版面）  ×  组件层（原语）
```

**全系统只有这一份。** 类型包**不复制它** —— 类型包只放差异，并在自己的 `compose.ts` 里声明
「我组合了哪些来源」。展示层照那份声明把内核的**元件层**（19 个原语 + `COMPONENT_SPECS` +
`Stage` 底色）与**组件层演示**（`KitShowcase` 及其夹具）补进类型包那一页；
运行时则靠那个类型包自己的 `master/MasterFrame.tsx` **适配器**把「内核引擎 + 本套件家具」组合起来。

内核**不需要 `compose.ts`** —— 它上游没有别的来源。

## 何时用

任何视频都要它 —— 但它是**内核**，不是最终外观。用法有两层：

| 怎么用 | 读哪 |
| --- | --- |
| **直接用内核**（单一通用视频） | 下面这张表 |
| **通过一个类型包用**（热点解析这类） | 那个类型包的 `kit.md` —— 内核由它的 `compose.ts` 补入，你不用手动接 |

| 你要的东西 | 从这里拿 |
| --- | --- |
| 换一套长相（色板 / 字体 / 字阶 / 圆角） | `theme/index.ts` 的 4 个主题，或照 `theme/default.ts` 复制一份 |
| **换一张皮**（框的形状与装饰，不动颜色） | `skins/index.ts` 的皮表 ＋ `<Panel skin="…">` —— 见下「皮清单」 |
| 母版引擎（家具 + 内容区预约 + 几何下发） | `master/MasterFrame.tsx` |
| 一套能直接跑的通用版式 | `master/layouts/` 的 6 个版式 |
| 溢出护栏（测量 / 截断） | `guards/fitting.ts`、`guards/ClampLines.tsx` |
| 开发期诊断（参数越界 / 时序溢出） | `guards/diagnostics.ts`（`warnOnce` 去重；`warnIfStaggerOverflows` 是 T06 的判据） |
| 契约原语（文字动效等） | `components/` |
| 机器可读的槽契约 | `master/types.ts` 的 `LAYOUT_SPECS` |
| **控制参数**（不是槽） | `master/types.ts` 的 `LAYOUT_CONTROL_PROPS` —— 「怎么排」类参数（`staggerInFrames`），**不进** `LAYOUT_SPECS`。判据见 `master-contract.md` §4 |
| 验证载体 | `templates/` 的 4 个演示合成 |
| 组件层验证（**故意不经过母版**） | `templates/Scene.tsx` —— 见下 |
| **类型专属家具怎么挂进来** | `master/types.ts` 的两个通用插槽 `headExtra` / `footExtra`（`master-contract.md` 有完整例子） |

## 什么时候不用母版（`Scene.tsx`）

**母版是标配** —— 三要素（家具 / 版式 / 槽契约）缺一个就退化成「一堆组件」。只有一个例外：

**组件层验证不走母版。** `KitShowcase` 用 `Scene.tsx` 而不是 `MasterFrame`，因为母版会带进来两样东西 ——
**家具**（报头 / 页脚 / 进度）与**内容区几何**（安全区预约与缩放）。它们会**遮蔽组件自身的行为**：
一个原语的位置或字号看着「对」，可能只是母版刚好把它摆对了地方。

| 验证哪一层 | 用什么 | 为什么 |
| --- | --- | --- |
| 组件层（原语） | `Scene.tsx` | **隔离** —— 看到的只能是组件自己的表现 |
| 母版层 | `MasterFrame`（默认主题） | 验家具与版式的配合 |
| 主题层 | `MasterFrame` + 换主题 | 同一份内容，差异只可能来自主题 |

**出片一律用母版。** `Scene.tsx` 只服务验证，不是成片可用的轻量替代品。

## 主题清单

| id | 长相 | 关键差异 |
| --- | --- | --- |
| `default-dark` | 深色现代 | Inter / 微软雅黑，冷蓝强调，圆角 4，边距 80/100 |
| `paper-seal` | 宣纸楷书 | KaiTi / FangSong，朱砂强调，方角，边距 96/112，横排更松 |
| `bubble-pop` | 卡通 | Comic Sans / 微软雅黑，荧光粉强调，粗胶囊（圆角 999），大字号小边距 |
| `neon-terminal` | 终端 | 全等宽 + FangSong，霓虹绿强调，1px 直角，最小边距 |

四个主题在**色板、字族、字阶、安全区、间距、动效签名、图形语言**七个维度上都不一样。
契约、命名规则与「0 行改动」硬指标见 `references/theme-contract.md`。

## 皮清单（T08 裁定）

**皮 ＝ 外观的具名预设**，由**调用处**点名：`<Panel skin="corner-marks">`。
它只声明**形状 / 结构的选择**（圆角档、角标），**不声明标量、不声明色值** ——
颜色仍全归主题，粗细归实例。所以三级优先是 **实例 prop > 皮 > 主题**。

| id | 差异项（就这两条） | 出处 |
| --- | --- | --- |
| `plain` | **空** —— 它就是现状 | 缺省皮。差异表为空是**判据**：机制本身必须不动画面 |
| `corner-marks` | `radius: 'square'` ＋ `cornerMarks: true` | 历史参考 `arch-v4.html` 的「图 2」 |

- **名字不存在时会直接抛错**（`resolveSkin`），**不静默退回 `plain`** —— 静默回退的症状是
  「画面看着正常，只是不像你以为的那张皮」，那种错不会有人发现。
- **标量不进皮表**：参考里那句「1px 细线」由调用处写 `borderWidth={1}`，不是皮的字段
  （§9.2：标量允许读主题默认值或由实例明确覆盖）。
- **首批只有这两张**，是裁定「选一到两种」的落地；加皮前先读 `skins/index.ts` 文件头那条判据
  （**定义性差异能不能靠现有能力 ＋ 至多一件小能力表达**，不能就先别建皮）。
  今天明确**没做**的两张与原因也写在那个文件头（`band-outline` 要改头的排法；
  `soft-round` 的彩色标题属于主题字段扩展，混进来会变成「两个都能改颜色」）。
- 四角角标那件装饰在 `skins/CornerMarks.tsx`。⚠️ 它**默认内缩 10px**：
  参考里框是 1px、角标 2px 所以贴角看得见；本套件框的粗细来自主题（默认 2px），
  贴角（`inset: 0`）时两者逐像素重合、抽帧出来**什么都看不见**（实测）。

## 依赖

**唯一额外依赖：`@remotion/layout-utils`（官方包，版本随 Remotion）。**

为什么不是「零依赖」：母版的溢出护栏必须**真的测量**。固定时长配变长内容，靠猜字号一定会溢出。这个包提供的 `fitText` / `fitTextOnNLines` 是唯一可靠的做法。

```bash
npx remotion add @remotion/layout-utils
```

## 安装

```powershell
Copy-Item "<SKILL_DIR>\kits\kernel" "<project>\src\kits\kernel" -Recurse
```

> ⚠️ **（新）装一个类型包时，内核也要装。** 类型包只放差异，原语在内核里 —— 只装它那一份编译不过。
> 两份一起装的命令见 `SKILL.md` 第七节。

然后注册演示合成（验证载体）。**主题演示按 `THEME_IDS` 批量注册**，一个主题一个合成：

```tsx
import {Composition} from 'remotion';
import {THEME_IDS} from './kits/kernel/theme';
import {KitShowcase} from './kits/kernel/templates/KitShowcase';
import {MasterShowcase} from './kits/kernel/templates/MasterShowcase';
import {ThemeShowcase} from './kits/kernel/templates/ThemeShowcase';

<Composition id="KitShowcase" component={KitShowcase} durationInFrames={1200} fps={30} width={1920} height={1080} />
<Composition id="MasterShowcase" component={MasterShowcase} durationInFrames={480} fps={30} width={1920} height={1080} />
{THEME_IDS.map((themeId) => (
  <Composition
    key={themeId}
    id={`ThemeShowcase-${themeId}`}
    component={ThemeShowcase}
    defaultProps={{themeId}}
    durationInFrames={480}
    fps={30}
    width={1920}
    height={1080}
  />
))}
```

## 用法

```tsx
import {getTheme} from './kits/kernel/theme';

<MasterFrame
  theme={getTheme('paper-seal')}          // ← 换主题只改这一行
  furniture={{
    masthead: {title: '夜读日报', meta: '第 042 期 · 2026-09-19'},
    footer: {
      left: '来源：内部整理',
      right: '内容自述',
      progress: {current: 2, total: 6},   // 整片级动效，随帧推进
    },
  }}
>
  <Sequence from={0} durationInFrames={60} premountFor={30} name="cover">
    <CoverLayout kicker="今日必读" title="…" meta="2026-09-19" />
  </Sequence>
  <Sequence from={60} durationInFrames={60} premountFor={30} name="headline">
    <HeadlineLayout index="01" title="…" summary="…" />
  </Sequence>
</MasterFrame>
```

要点：

- **家具在母版层渲染一次**，不要在场景里重复报头；
- 版式**只管内容区**，不重复家具、不改安全区；
- 版式入场动效从**该序列的本地 0 帧**起算；
- 换主题只换 `<MasterFrame theme={...}>`，版式一行都不用改；
- 原语的色 / 字族也来自主题（`useTheme()`），不用逐处改。

## 六个版式的槽契约

见 `master/types.ts` 的 `LAYOUT_SPECS`（机器可读）。摘要：

| 版式 | 槽 | 溢出策略 |
| --- | --- | --- |
| `cover` | kicker? · title · meta? | fit · **fit-n-lines** · fit |
| `headline` | index? · title · summary? | none · **fit-n-lines** · clamp |
| `list` | title · items[] | fit · fit（逐条 + 按条数收行距） |
| `stat` | value · unit? · label · note? | fit · fit · fit · clamp |
| `quote` | text · attribution? | **fit-n-lines** · fit |
| `closing` | title · meta? | **fit-n-lines** · fit |

**`lines` 槽的编码约定**：`items` 这一类槽的每条是 `'主字段<TAB>说明'`，用 **TAB** 分隔
（文案里出现逗号和竖线是常态，TAB 不会）。解析只有一份实现：`master/slots.ts` 的 `splitEntry`。
**没有分隔符时整条当说明**，此时 `list` 退回**单列整宽** ——
所以「普通清单」与「带主字段的对照清单」共用同一个版式，两条分支在演示合成里**各摆了一遍**。

**必填槽必须完整显示**（所以是 fit-n-lines：缩字号）；**可选槽显示不完没关系**（所以是 clamp：截断）。

## 渲染配置档

纯 DOM，无 WebGL、无外部素材、无字体下载 —— **无特殊渲染要求**。

```bash
npx remotion render <comp-id> out/draft.mp4 --scale=0.5 --crf=28 --jpeg-quality=70
```

抽帧时 `--scale=0.5` 就够做主题对比（色彩 / 字体 / 尺度都能看清），交付前再全分辨率抽查一张。

## 已知限制

| 限制 | 对策 |
| --- | --- |
| 用网络字体时，字体未加载则测量不准 | 先 `waitUntilDone()` 再渲染；或改用系统字体。**字体栈必须点名目标环境里真实存在的字**，否则中文字重会逐段回退，同帧混排宋体 + 黑体 |
| 母版层从主题取缓动（`theme.motion.enter`），在 Studio 里不可逐处编辑 | **有意为之**：动效签名属于主题。⚠️ **原语层（`components/`）的缓动虽然内联，今天也不可编辑** —— 2026-10-05 实测全层 `keyframed` **0** 格；内联只是必要条件，成因与读数见 `references/component-contract.md` §3 |
| 护栏算出的字号是「计算值」，Studio 不可编辑 | 同上 —— 护栏的职责是「不溢出」，不是「可微调」 |
| 原语的字号默认值是内联常量（如 `Title` 的 96），不跟随主题字阶 | **有意为之**：Studio 只能编辑内联值。要跟随主题就显式传 `theme.type.title`，或直接用版式 |
| 版式的 `name`、`.map()` 出的行名由索引算 | Studio 可选中，回写不如硬编码名字稳定 |
| 暗角会压暗边角，而报头 / 页脚在边角 | `muted` / `furniture` 偏暗的主题要把暗角收浅（`neon-terminal` 抽帧后就是这么修的） |
| **`MediaCard` 不校验 `from` / `to`** | 它按帧坐标绝对定位，两个矩形由调用方给 —— 组件**在渲染路径里不许测量**，所以它没法知道你给的 `from` 是不是它真实所在的位置。给错了它不会报错，只是落在错的地方 |
| **`MediaCard` 的展开要自己给 `to`** | 「居中 + 70% 宽」这类构图是调用方算的。组件不猜排版 |
| **`MediaStage` / `MediaCard` 没有入场动效** | **有意为之**：它们是承载内容的框，什么时候出现、怎么出现属于调用方（`<Sequence>` / `focus`） |
| **演示视频靠 `import` 一个 mp4** | 在 Remotion 自己的打包器里由 webpack 处理；**展示页的 esbuild 需要一条 `.mp4 → dataurl` loader**（`generate.ps1` 里已加）。⚠️ 但**渲染时不能用 data URI** —— `<OffthreadVideo>` 会把它交给取帧服务，服务取不到 `data:` 协议（实测渲染直接失败） |
| `MediaStage` 的 `src` 与 `kind` 是分开的两个 prop | **有意为之**：不去猜扩展名（`a.png` 与 `a.png.mp4` 都合法）。给了 `src` 就必须给 `kind` |
| **`ScrollArea` 只在渲染期量一次尺寸** | 内容在渲染期不会变，所以量一次就够。**要动态换内容，请换 `key` 让组件重挂载** —— 否则量到的还是旧的 |
| **`ScrollArea` 的 `scale` 为 0 时兜成 1** | 宿主在量出自己的尺寸之前可能给 0（画廊的格子就是）。不兜会得到 `Infinity` |
| **`ScrollArea` 只平移一整个内容块**（素材 / 结构的边界在这儿） | ① **钉表头**：「钉住素材的一部分」做不到 —— 一张截图里**没有「表头」这个对象**；`header` prop 钉的是**独立元素**（结构）。截图要钉，只能在**素材制作那一步**把表头切成另一张图（那张图自己有高度），或从图里裁一条出来（`clip` 是**写死的像素**，缝 = 带高 − `clip`：宽 1000 时实测 **18.3px**、正文顶还会重影 22 图象素）。② **锚行**：结构版的行高是**代码里的数**（`ROW_H`），截图版只能靠**源坐标标注**（图内表头高 / 行高）× 显示 scale —— 实测目测差 1px，第 k 条就偏 ≈k px（k=7 时 **7.5px**）。③ **首行 / 末行居中没有解**：`y` 必须落在 `[0, max]` 内，本夹具里 k=11 贴底后偏 **74.0px**。读数与复跑：`docs/2026-10-06-锚点与素材结构-待裁定.md` |
| **`MediaStage` 不提供滚动 API，长内容交给 `ScrollArea`** | `MediaStage` 只负责「把内容塞进框里」（`fit` / 标签条 / 框）；要**滚动显示**长内容就换成 `<MediaStage><ScrollArea scroll>…</ScrollArea></MediaStage>` —— 机制在 `ScrollArea` 里：内容放进 `children`、绝对定位、按 `scroll` 平移，超出部分由它自己的 `overflow: hidden` 裁掉（视频里没有「滚动」这个动作，所谓滚动就是**框不动、内容按帧平移**）。⚠️ **「滚多远」由 `ScrollArea` 自己量**（见 `references/component-contract.md` §6：**测量是允许的**，条件是别在补间里测、要除以 `useCurrentScale()`）。早先这里记的「组件不许测量、所以滚多远只能由调用方声明」是**错的推论**，已作废 |

### `from` 现在也是**入场的时间原点**（2026-10-06 修掉）

**症状（改前）**：`from={30}` 传原语 ⇒ **挂载那一刻入场就已经结束了**（墨量比 **1.000**，
而对照组「调用方自己包 `<Sequence from={30}>`」同一帧是 **0.000**）—— 静默、不报错、不警告。

**成因**：`Interactive.*` 内部建的是 `<Sequence layout="none" from={from ?? 0}>`，它挪的是
**DOM 挂载窗口**；而入场的值是用组件**体内**的 `useCurrentFrame()`（＝**外层帧**）算好的
（`remotion/dist/cjs/Interactive.js`）。

**修法（11 个元件层原语）**：`const localFrame = frame - (from ?? 0)`，入场与一切帧相关取值都读它 ——
那正是 Sequence **子树**里会拿到的数。**DOM 一个字没动**，`from` 缺省时 `localFrame === frame`
⇒ 现有调用逐帧不变。（更详细的读数：`docs/2026-10-06-from语义-裁定与落地.md`。）

**语义变了，两句话记住**：

| 想要的 | 旧写法（现在**不对**了） | **新写法** |
| --- | --- | --- |
| 从第 30 帧开始入场 | `<Sequence from={30}>` 外包，或 `from={30}`（其实是坏的） | **`from={30}`** |
| 再晚 30 帧入场 | `from={30}` ＋ `delayInFrames={30}`（旧语义下等价于外包 ＋ delay 0） | `from={30}` ＋ `delayInFrames={30}` ＝ 外层第 60 帧；或直接 `from={60}` |

**判据（都当场跑过）**：改后 `from={30}` 与「外包 Sequence」**逐帧相同**；
**22/22 抽样静帧逐字节相同**（`KitShowcase` ＋ `MasterShowcase`，改动前后各一遍）
⇒ 不用 `from` 的调用**零变化**；Studio 可编辑性**一格没动**（42 处 / static 148 / computed 230，与改前逐行相同）。

**四条设计决定**（都是被约束逼出来的，不是偏好）：

1. **两个原语而不是一个 + `variant` 枚举** —— 展示页上是两格，能分别指着说改哪儿；
   而 `focus`（缩放驱动量）只属于 `MediaCard`，挂在 `MediaStage` 上会是一个无效 prop。
2. **`MediaCard` 是绝对件，`from` / `to` 都由调用方给** —— 组件在渲染路径里不许测量，
   而「移到画面中心」要求知道它现在在哪。这与展示页 `ElementCell` 的 `home` 同源：
   **元素自己没有位置，必须指定一个**。
3. **`focus` 不做缓动** —— 它是驱动量（与 `ProgressBar` 的 `progress` 同理）；
   替调用方选一条曲线，就是替它决定了这一支片子的节奏。
4. **补间的是 `left/top/width/height`，不是 `transform: scale`** —— 绕开
   `transform-origin` / 单位 / `perceptual-scale` 三个坑，代价是每帧重排（几个框无所谓）。

**两处行为修正**（用户看片后提出 —— 都是 bug，不是当初的选择）：

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 标题在**放大到一半**时从下沿**跳到**上沿 | 换边判据写成了「展开到几成」（`focus ≥ 0.5`），而补间是连续的 —— 这次**离散**变化落在了补间的正中间 | 判据改成「**在不在展开态**」（`focus > 0`）：`focus` 一离开 0 就已经是展开态，所以换边也在那一帧。**离散变化要落在边界上，不能落在连续量的中段** |
| 展开的框**被右列那两个静止框压住**（右半边被切掉） | 三个框都是绝对件，层序由 **DOM 顺序**决定 —— 展开的是第 1 / 第 2 个，天然排在后面那些下面 | 层序 = 展开度：`zIndex = Math.ceil(focus × 100)` |

**第 5 条设计决定（由上面第二条逼出来）：层序也是 `focus` 的函数。**

它**不是新输入** —— 和 `from` / `to` 一样，只是把同一个驱动量多映射一个输出。
用 `Math.ceil` 而不是 `Math.round`：要的不变式是 **`focus > 0` ⟺ `z > 0`**；
`round` 在极小的 `focus` 上会退化成 0、与静止框并列，于是展开的头一两帧仍会被盖住。
静止时全是 0 —— 仍由 **DOM 顺序**决定，**静止排版与加这一条之前逐像素一致**。

组件**不提供**「层序」这个 prop：展开态本该就在最上面，那是这个交互的定义；
真要让某个静止框压在展开框之上，把它**包一层带 `z-index` 的外壳**即可。

**这两条各由什么验的**（别以为展示页把两条都管了）：

| 修正 | 验收手段 | 为什么是它 |
| --- | --- | --- |
| 层序 | **展示页断言**（第 48 条） | 画廊那一格**就是**三个框的堆叠，静止帧就能读到 `(z-index, DOM 顺序)` 与面积；判据取「**视觉最上层 = 面积最大**」这个**结果**，不是实现细节 |
| 换边时机 | **只能靠抽帧** | 画廊每格定格在 `demoFrame`，而 `MediaCard` 的 `demoFrame = 40` 就是 `focus = 1` 那一帧 —— 此时**新旧规则都判「上沿」**。这个 bug 只存在于 `0 < focus < 0.5` 的窗口里，**静止帧看不到**。所以抽帧抽的是 362（`focus≈0.012`） |

> 第 48 条断言**实测会红**：把 `zIndex` 改回 `0` 重新生成，它报
> 「最大的是 #1(z=0)，最上面的是 #2(z=0)」并让整轮验收失败；改回来即通过。
> **断言必须证明过它会红** —— 一条永远绿的断言等于没有。

**三条设计决定**：

1. **单独一个内容件，`MediaStage` 一行不改** —— 参考形态是「框 + 钉住的标题栏 + 会滚的正文」，
   而 `MediaStage` 的标签条是**压在内容上的图说**（图片本来就该铺满整框），不是**占位的标题栏**。
   所以标题栏交给 `ScrollArea` 的 `header`，`MediaStage` 只给框（**不给 `label`** 就没有标签条）。
   拆分的额外好处：量尺寸那套机制不必进 `MediaStage`。
2. **内容高由组件自己量**（`useCurrentScale()` + `ref` + `useEffect`，官方做法），
   `contentHeight` 只作为**覆盖**。这样「滚多远」不必由调用方声明 ——
   而声明错了会**静默变空**（实测过：声明 2200、实际 1409，滚到底那一帧框里什么都没有，不报错）。
3. **轨是「窗口戏服」，可选、默认不画**。真实片子里有滚一张长表格但**完全不要轨**的
   （靠底边切掉半行就足以提示「还有」）；要轨是因为这个框想读成**一个真的窗口**。
   几何照**真滚动条**（滑块长度 = 可见高 / 内容高，位置 = `scroll`）——
   动机既然是拟真，几何就该照被模仿的那个东西。

**两个实测坑**（都只有抽帧能抓到）：

| 坑 | 症状 | 根因 / 修法 |
| --- | --- | --- |
| **首次 `useEffect` 里视口量到 0** | 滚到中段还正常，**滚到底框是空的**（内容被整个推出框外），不报错。逐帧看是**确定性**的，不是竞态 | 视口是**弹性子项**，那一刻高度还没解出来；内容层是绝对定位的、高度不依赖弹性布局，所以**它量对了**。于是 `max = 内容高 − 0` 偏大。修法：**`ResizeObserver` 再量一次**（这也是 Remotion 的「测量 DOM 节点」那页末尾指向 `react-use-measure` 的原因） |
| **画廊整页白屏**（11 条断言一起红） | `Uncaught Error: useCurrentScale() was called outside of a Remotion context.` | 画廊是**手搭的 Remotion 环境**，没提供 `Internals.CurrentScaleContext`；而且画廊每格自己 `transform: scale()`，所以要**按格**喂**那一格自己的** scale（传常数 1 会让测量差一个倍率）。已在 `gallery/stage.tsx` 加 `ScaleProvider`，元素格与版式 / 家具格都包上 |

**给下一轮的一句话**（**2026-10-06 兑现**）：`ScrollArea` 只**平移一整个内容块**，所以「滚到某一行」必须由**帧**算出
`scroll`。算式里唯一「调用方未必知道」的数是**视口高**，而组件已经量过它 ⇒ 现在配了一个**最小尺寸通知**
（`onMeasured`）＋ 一个**通用定位计算**（`anchorScroll`）。读数与边界见下一小节。

**三条设计决定**：

1. **`TextTag` 是 `inline`，成排是调用方的事。** 判据照 HTML：一枚标签就是
   `<span class="chip">`，它**自己没有盒子**（与 `Emphasis` 同理）。组件不替调用方决定
   一排几枚、要不要换行 —— 那是排版。四种分量是**四个重量档**（`solid` → `tint` → `outline` → `muted`），
   不是四种颜色；全用 `solid` 等于没有重点。
2. **`RichTextBox` 的输入是字符串，不是 runs 数组。** 理由是**槽位传进来就是字符串** ——
   只有这条路能让「一句里有三个词要强调」从数据层来。标记只取三种：
   `**加粗**`（重量）/ `==高亮==`（落点）/ `` `等宽` ``（字面量）；没有取 `__下划线__`，
   因为 `_` 在代码内容里太常见（`__init__`）。**高亮复用 `Emphasis`** —— 画法只有一份实现。
3. **`BarChart` 的数值列固定宽、右对齐，不骑在条的末端。** 骑在末端会随条的成长一路移动，
   一屏里所有数字都在动；固定成一列之后**只有长度在动、数字是静止的参照**，而且条到 100%
   时数字也不会被挤出去。名字叫 `BarChart` 而不是 `HBarChart`：中文里「条形图」本来就是横的
   （竖的叫**柱状图**），`ColumnChart` 那个位置留给以后真要做竖排时用。

**两条实现细节**（都是「不做就会静默出问题」的那种）：

| 细节 | 不这么做会怎样 |
| --- | --- |
| **标签的四种分量共用一套盒子几何**（实底 / 淡底也写 `1px solid transparent`） | 边框宽度**参与布局**：描边的那两枚会比实底的那两枚**高 2px**，同一排里高低不一。已由展示页断言钉住（比的是**未取整**的高度，容差 0.05px —— 格子套了 scale ≈0.15，2px 到画面上只剩 0.3px） |
| **条的生长不用 `perceptual-scale`** | 一维生长（`'0 1' → '1 1'`）**编码的是数据**，加感知曲线等于把数值一起弯掉。`perceptual-scale` 是给**二维均匀缩放**的（`TextTag` 的弹出、`BulletList` 的方块才用它）—— `Emphasis` 的一维生长同样不带 |

**一处越层依赖（有意为之）**：`BarChart` 从 `../master/slots` 取 `splitEntry`。
组件依赖母版层看起来是反的，但**槽编码只能有一份实现** —— 各写一遍就是「改一处漏一处」，
而本套件已经因为「版式自己解析」吃过一次亏（见 `ListLayout` 的缺陷记录）。

**顺带把 `lines` 槽的归属讲清楚**（查过一遍，**不是缺陷**，是一条边界）：
`lines` 槽属于**版式**（`LAYOUT_SPECS`），所以**解码是版式的责任** —— 组件收到的是字符串数组。
实测：`BulletList.items` / `TextReveal.lines` 都声明成 `kind: 'lines'`（= 「形状与 `lines` 槽相同」），
它们**不解码**，而**没有任何版式把未解码的槽原文交给它们**（`ListLayout` / `TimelineLayout` /
`StanceLayout` / `MultiStatLayout` 四个消费者都先 `splitEntry`）。
`BarChart` 是这条边界的**例外**：它的数据模型**本身就是两个字段**（标签 + 数值），
一个字符串装不下，所以它自己解码 —— 用的是同一份实现。
**要守住的是**：以后若有版式把带 TAB 的数组直接交给 `BulletList`，TAB 会被 HTML 塌缩成一个空格、
主字段与说明的区别静默消失（与 `ListLayout` 那条同源）。

### 新增一个原语：`Panel`（内容卡）

需求：用户从网上视频里截了四张图，明确说「**主题不是重点，而是这个「框」的功能**」。

**先把「框」的功能拆出来** —— 四张图恰好是它的四个职责：

| 职责 | 图里的证据 | 对 API 的要求 |
| --- | --- | --- |
| **注意力单位** | 三行清单是**各自一个框**，不是一个框包三行 | 要有强调态（讲到别处时压暗） |
| **引用范围** | 框的是一段**外来内容**，评论性的标签贴在框上 | 描边划界；来源 / 状态挂 `header` / `footer` |
| **比较单位** | 两张数字卡并排 | `children` 必须内容无关 |
| **标注挂点** | 「正文未提」「未交付」都贴在框的边缘 | `footer` 贴在框底 |

**用户当场裁定了两条，都改掉了设计**（记在这里，免得以后有人又加回去）：

1. **「不是滚动，是硬切换」** → 所以**不做窗口**：不接 `ScrollArea`、没有 scroll prop、**不裁切**。
   ⚠️ **措辞更正（用户后来指出）**：参考里的真实机制是「**原位替换**」—— 同一个框，
   **内容区直接换成下一页**；因为字少了，**窗口跟着收紧**。我起的「硬切」这个词**容易被读成「翻页」**，
   以下一律按「**原位替换**」理解。
   ⚠️ 顺带说清**为什么不能补间**：契约**禁止动画 `height`**，而缩放整个框会把字也缩放（变形）
   —— 所以框高是**离散**变化的。这既合规，也正是「原位替换」该有的样子。
   ⚠️ **前提：框必须顶部锚定**（`alignItems: 'flex-start'` / 绝对定位给 `top`）。
   第一版演示就踩了：`Scene` 默认 `align="center"`，于是框是垂直居中的 —— 收紧时**上下一起缩**，
   看起来是「窗口在跳」。抽帧一比两帧的上边缘（`270` vs `358`）才看出来。**已改成 `align="top"`**。
2. **「框的大小跟内容有关，前一页高一点、后一页低一点」** → 所以**没有 `height` prop**、也不拉齐。
   （我原本倾向「摆放定高 + 护栏适配」，**被否了**。）
3. **演示也跟着改了**：Scene 12 原来摆成「两张并排的卡」，**看不出替换与收紧**；
   现在改成「**一张卡在第 30 帧原位换正文（连同页码）+ 窗口收紧**」，右侧那张留给 `dim`。

### 新增一个原语：`Stat`（大数字）+ `Panel` 的宽度旋钮

需求（用户裁定）：① `Panel` 没有宽度旋钮，而**每一个**别的块级原语都有
（`maxWidth`），于是「紧凑块」只能靠在外面套一层 `display: flex` 的壳；② **单张卡**的场景
（一个数据点，参考图 2）缺一个原语 —— 主题里的 `type.stat` 当时只有版式在消费。

#### `Panel` 的 `width`：三档，不给对齐

| 档 | 值 | 语义 |
| --- | --- | --- |
| 撑满 | 省略 | 撑满给它的盒子（在 flex 行里则按内容 —— 那是浏览器的规则） |
| 定宽 | 数字 | 固定像素宽 |
| 收紧 | `'fit'` | **跟内容走**（紧凑块）：收到内容那么宽 |

两条实现上的决定：

1. **数字按 `border-box` 算** —— 所以「`width={600}`」量出来就是 600，而不是 600 + 内边距 + 描边。
   `boxSizing: 'border-box'` 是**无条件**写的：`width: auto` 时它什么都不影响，所以不必分两条路。
2. **外框（`Interactive.Div`）与卡身给同一个值** —— 只给卡身的话，父容器是「撑满」的块时，
   一张定宽卡会贴在左边，看起来像**没居中**。宽度必须同时作用在「长相」和「占位」上。

**为什么不做对齐**：卡不知道自己在画面里站哪儿。一旦它知道，就会和母版 / 场景的位置打架 ——
「居中还是靠左」属于**外面那层容器**。

#### `Stat`：一个数据点

先把「大数字」的功能拆出来 —— 与 `Panel` 同一套做法：

| 职责 | 靠什么实现 |
| --- | --- |
| **① 落点** —— 前面铺垫、数字出现、后面解释 | 三段**错开**入场：数字先落 → 单位跟上 → 标签最后（整段长度是一个 prop） |
| **② 量级** —— 「大」本身就是信息 | 字号远大于正文；入场是 `scale` 从 0.86 **长**上来（原点在**基线**），不是滑进来 |
| **③ 单位不属于数字** —— `%` 不该跟着放大到 160px | `unit` 是**另一个**行内元素，同排**按基线对齐**，字号按 0.3 推 |
| **④ 格式化属于内容层** | `value` 是**字符串**，组件一个字都不解析 |

**为什么不是「`Title` 加大字号」**：三处都不一样 —— **基线**（单位与数字靠 `baseline` 对齐，不是居中）、
**原点**（`scale` 从左下 / 中下长起）、**字族**（数字用 `font.mono`）。一个「大一点的标题」量不出这三样。

**与 `stat` 版式的分工**（不是重复）：版式跑**整卷**、有**溢出护栏**、槽是字符串；
原语是**可组合的叶子** —— 单张卡里放一个数据点、或者放进 `Panel` 当卡身。要护栏就用版式。

**两条写断言时踩到的坑**（都是**判据**写错，不是组件错 —— 记下来免得下次再写一遍）：

1. **`[data-cell="Stat"]` 里的 `.el` 子元素形状与 `Panel` 不同**：`Panel` 的演示根是一个 **Fragment**
   （两个兄弟），`Stat` 的根是一个**列**。取 `el.children` 会少一层，断言会报「格子不存在」——
   而格子其实在。**判据要照着自己那一段演示的真实结构写**，别照抄隔壁的。
2. **「数字自己的中心」不是对齐的判据**：有单位时，数字左边还留着 `gap + 单位宽`，
   所以 `justifyContent: center` 之下**数字的中心本来就不等于容器中心**（实测差 43px —— 那是正确的）。
   要量的是**整行内容的跨度中心**与**收缩到内容的标签的中心**。
3. **基线对齐的判据不能写死像素**：`align-items: baseline` 之下，单位与数字的底边差 = `(H−h)·(1−a)`
   （`a` = 字体的基线高度比），随字族变。写成**与高度差成比例**就与字体无关：
   底边差 < 高度差的 0.4 倍（居中恰好是 0.5 倍），且中线差 > 高度差的 0.1 倍（居中时是 0）。

**一条边界**：`Stat` 与 `Panel` 是**两层不同的东西** —— `Panel` 给边界（引用范围 / 注意力单位），
`Stat` 给数据点。单张数据卡 = `<Panel width="fit"><Stat … /></Panel>`；
⚠️ 但**不是必须** —— `Stat` 单独站在场景里完全成立（Scene 13 就是这么摆的）。
`Panel` 的演示里摆了三张卡做 A/B 对照（那是**对照**，不是「必须带三张」）。

### 大数字的三条「动态」：跳动 / 计数到 / 数位滚动

需求（用户提问后裁定）：**「这个大数字是否可以动态变化？比如从前一帧到后一帧数字发生跳动」**，
三条都要。

**先分清三种形态 —— 它们的责任方不同，这是这一轮唯一重要的设计判断**：

| 形态 | 怎么做 | 谁负责 | 新增 API |
| --- | --- | --- | --- |
| **跳动** —— `86.6` → `91.2` 一帧换掉 | 调用方按帧换 `value` 字符串 | 调用方 | 无 |
| **计数到** —— `0.0` → `86.6` 连续长 | 调用方每帧 `interpolate` **数值**、再 `toFixed` 成字符串 | 调用方 | 无 |
| **数位滚动** —— 每一位上下翻 | `rollFrom` + `roll`，组件逐位平移 | **组件** | 2 个 prop |

前两种**不需要组件知道那是个数字** —— 这正是「格式化属于内容层」这条裁定换来的：组件只把字符串印出来。
第三种是唯一需要组件参与的（它得知道「哪一位滚到哪一位」），所以多一个起点字符串。
**两条都得用眼睛看**：计数到是数字**跳**（整串换掉），滚动是数字**滑**（每一位上下走）。

#### `reserveChars`：为什么「跳动」和「计数到」都需要它

等宽族保证「**同位数**换值整行不动」（`86.6` → `87.1` 宽度不变），但**位数一变就会晃**：
`9.9` → `10.2` 多一位，**单位被推着往右移**。而计数到（`0.0` → `86.6`）从头到尾都在变位数。

**机制是「幽灵占位」**：同一字体、同一字号、同一行高渲染 N 个 `0`，让它当**宽度与基线**的捐赠者；
真值（或滚动列）绝对定位盖在它上面。选它而不是 `minWidth: Nch` 是因为：
`ch` 是字体度量，而 `letterSpacing` 会让实际宽度差 `N × 字距` —— 幽灵与真值同字体同字距，**精确相等，不依赖任何度量**。

**实测证据**（`KitShowcase` 计数到那一场，单位 `%` 的像素位置）：

| | frame 854（值是 `0.7`，3 位） | frame 866（值是 `43.3`，4 位） | frame 880（`86.6`） |
| --- | --- | --- | --- |
| **有** `reserveChars={4}` | x **1124** | x **1124** | x **1124** |
| **去掉** `reserveChars` | x **1080** | x **1124** | x **1124** |

→ 没有它，位数一变单位就**跳 44px**；有了它，三帧**一像素都不动**。

#### ⚠️ 数字区**故意不加** `letterSpacing`（母版 `StatLayout` 的 `-2` 没有跟过来）

逐位滚动靠一个不变量成立：**N 列（每列 `1ch`）必须正好铺满 N 个字符宽**。
字距会让列宽与幽灵差 `N × 字距` 像素 —— 列与占位错开，最后一列被挤出框外。
等宽族本来就够紧，少一个会让两套机制打架的旋钮。**这条有断言钉着**（见下）。

#### `rollFrom` + `roll`：逐位线性，**不是**数值插值

每位从 `rollFrom[i]` 滚到 `value[i]`，滚过的字形是 `a..b`（含两端，正反都行）；`.` / `,` / 非数字不滚。

⚠️ **它不等于计数到**：`'0'` → `'99'` 的中点是 `'55'`，不是 `'49.5'`。要**数值正确**就用前两种。

⚠️ **`rollFrom` 必须与 `value` 等长**，不等长时**不滚**（直接显示 `value`）——
长度不同就无从判断「谁对上谁」，而**猜**比不动更坏（与 `BarChart`「测不出数就显示原文」同一条裁定）。
症状是「它不动」，看得见。演示里**两条都摆**（Scene 14 左等长 / 右短一位）。

### 元素格子的「越界与贴边」：居中的断言为什么没拦住它

用户提的（附截图）：**「改一下它们的位置，当前已超出内容区域了」**。

**一测就发现「居中」那条断言一直是绿的** —— 因为安全区与画布**同中心**，
所以一个**比安全区还大**的盒子会**两头都越出去**，而「元素居中在画布里」照样成立。
这正是判据写错了层：**「居中」不等于「在内容区里」**。

实测四边余量（画布坐标，安全区内容区 = (80,100)–(1840,980)）：

| 元素格 | 修前 | 修后 |
| --- | --- | --- |
| `Stat` | 上 14 / 下 13（**贴边**） | 上 109 / 下 109 |
| `Panel` | 上 38 / 下 37（**贴边**） | 上 170 / 下 169 |
| `MediaStage` | 上 **−54** / 下 **−55**（**真越界**） | 上 0 / 下 0（16:9 满幅，**故意**） |

**三处修法**（前两处是演示摆错了，第三处是组件本身就错）：

1. **`Stat` 的演示**：四条叠起来时字号 120 让盒子有 853 高 → 改成字号 90、条间距 30 → 24（高度 653）。
2. **`Panel` 的演示**：**从上下叠改成左右并排**（805 → 532）。
   ⚠️ 而且宽度是**算出来的，不是看着差不多**：演示盒是**绝对定位 + 收缩到内容**，
   所以它的宽 = 两段各自 max-content 之和；而 `Panel` 的 max-content = `RichTextBox.maxWidth`
   ＋ 内边距（28×2）＋ 描边 —— 给 460 时一长一短那一段就有 1064 宽，加上宽度段的 700，
   整盒 **1804 > 1760**，右侧被切掉（实测余量 13px）。改成 300（两段各 360 → 744）后合计 1480。
   ⚠️ 宽度那一段**不能再窄**：它是验收里 `fit` 的对照（判据 `fit < 撑满 × 0.7`），
   700 之下 `fit`（实测 432）才明显更窄。
3. **`MediaStage` 的默认尺寸本来就是错的**：它取的是安全区的**宽度**（1760），
   而 16:9 的 1760 是 **990** 高 —— 安全区只有 **880**，于是框**上下各越出 55px、压进报头与页脚带里**。
   安全区是硬契约，所以默认改成**安全区里放得下的最大 16:9**（这里 1564×880）。
   要更大的框就显式给 `width` —— 那时越界是调用方的选择。

#### 新断言 4q：不越界，而且（满幅 16:9 之外）要留出余量

判据取**结果**，换算到画布坐标：

* **不越界** —— 元素盒必须落在 `.cellsafe` 里（硬规则，无例外）；
* **余量 ≥ 32px** —— 除非这个盒子本身就是**满幅的 16:9**（`MediaStage` 的默认尺寸就是
  「安全区里放得下的最大 16:9」，它**故意**上下贴满）。判据取**结果**（这个盒子是不是 16:9），
  **不取名字** —— 与「16:9 且撑满画布」那条同一个写法。
  ⚠️ 为什么要这条：**贴边与越界在截图上是同一个观感**，而余量是唯一能区分它们的数。

**两个判据本身的坑**（都是**量错**，不是组件错）：

1. **参考系必须取 `.cellinner`**（它就是 1920×1080 等比缩放的那一层）。
   拿 `.cellbox` 当参考系会带上它的边框 / 内边距 —— 实测把安全区左边界算成 **88**（真值 80），
   四边余量整体偏 8px / 4px，「贴边」与「越界」就分不清了。
2. **`offsetWidth` 是取整的，别把一串加起来**：数位滚动的列宽断言原来把 4 列的
   `offsetWidth` 相加，每列 49.4px 被各自舍成 49，**累出 2px 的假差**（字号 90 之下翻的车）。
   改量**轨容器**的宽（只取整一次）即可。

### 新增一个原语：`Flow`（排列）＋ `Panel` 可被拉伸 ＋ 版式节奏可覆盖（2026-10-03）

一条主线：**「一屏怎么分」以前只能手写 flex** —— 调用方要给每个子项套壳、自己写
`flex: '2 1 0'`、自己处理长内容撑爆轨道（`min-width: 0`）。现在这三样都在**容器**上：

| 交付 | 落点 |
| --- | --- |
| **比例 / 间距 / 三档尺寸** | 新原语 `components/Flow.tsx`（`display: container`）：`ratio` / `gap` / `sizing` |
| **元素可被拉伸** | `Panel` 内层**无条件** `height: 100%`（**不加 prop**）—— 父级给了确定高度就撑满 |
| **本期节奏** | 五个版式各加 `staggerInFrames`：**显式值原样生效，不参与收紧**（写这段时是**实现现状、未裁定**；**2026-10-05 T06 已裁：原样生效 ＋ 溢出诊断**，见本节末） |

**三条判据（都证明过会红）**

### 复跑命令

```powershell
$lab="<LAB>"; $k="<SKILL_DIR>\kits"
# 母本 → lab：两份**都**要同步（lab 里那份是母本的拷贝；类型包不带内核）
foreach ($s in @('kernel','hotspot')) {
  Copy-Item "$k\$s\*" "$lab\src\kits\$s" -Recurse -Force
}
Push-Location $lab
& "$lab\node_modules\.bin\tsc.cmd" --noEmit
& "$lab\node_modules\.bin\remotion.cmd" compositions
# 按**场景序号**抽帧，不手写帧号 —— 场景数变了（`list` 演练两次）也不会漏
foreach ($i in 0..6) {
  & "$lab\node_modules\.bin\remotion.cmd" still MasterShowcase "out/m-$i-mid.png" --frame=$($i*60+30)
  & "$lab\node_modules\.bin\remotion.cmd" still MasterShowcase "out/m-$i-end.png" --frame=$($i*60+56)
}
foreach ($t in @('default-dark','paper-seal','bubble-pop','neon-terminal')) {
  foreach ($i in 0..6) {
    & "$lab\node_modules\.bin\remotion.cmd" still "ThemeShowcase-$t" "out/$t-$i.png" --frame=$($i*60+30) --scale=0.5
  }
}
Pop-Location
```

然后**用看图工具逐张看** —— 这是唯一可靠的验收方式。
