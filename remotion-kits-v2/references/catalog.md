# 套件目录

**已沉淀的套件** —— 历次创作的产物。**本表只列真实存在的**：一个套件进了这张表，就意味着它自带
主题与演示合成、并且按版式抽过帧。

框架里有两类东西，**但它们不是「两个套件」那种关系**：

| | 覆盖什么 | 内容 |
| --- | --- | --- |
| **`kernel`（内核）** | **任何视频都要它**：契约原语、通用版式、通用家具、主题、溢出护栏 | 19 个契约原语 + 母版引擎与 6 个通用版式 + 2 件通用家具 + 4 个主题 + 演示合成。**全系统只有这一份** |
| **`hotspot`（类型包）** | **热点解析** —— 事件脉络、各方立场并列、多个数字对照 | **只放差异**：3 个专属版式（`timeline` / `stance` / `multi-stat`）+ 2 件专属家具（事件时间戳、来源与可信度）+ 2 个主题 + 自己的母版 / 主题演示 ＋ `compose.ts`（声明它组合内核）。原语与组件层演示**不在它这里** |

> ⚠️ 类型包**必须连内核一起装**（它自己没有原语），见 `SKILL.md` 第三节。
> 展示页上类型包那一页会把内核的元件层与组件层演示**补进来**，页头写明来源 —— 那是
> **合并视图**，不是「这个类型包自己拥有那些原语」。

**表里没有的类型 → 走 `creation-workflow.md` 造一套。**

本框架**不预置尚未存在的套件**：类型是用户提出时才存在的，任何提前承诺都会先于事实。
所以这张表是**沉淀记录**，不是路线图。

## 常见类型的版式构成参考（**创作起点，不是可用性承诺**）

用户点名的类型，可以照下面的起点直接进 `creation-workflow.md` 第 1 步；表外的类型同样从第 1 步
现做（这套方法本来就是为「没见过的类型」准备的）。

> ⚠️ **取材缺口**：下面这几节**只覆盖用户实际点过名的类型**，不是一张穷举表。
> 遇到表外的类型**不要硬套**最近的邻居 —— 从第 1 步「这类视频每期都在讲哪几种东西」重新拆。
> 补一节的判据是：**真的有一支片子这么做过了**（抽过帧、验过），不是「想得到」。

### 新闻日报 / 每日资讯

| 信息形态 | 建议版式 | 内核那 6 个版式能覆盖吗 |
| --- | --- | --- |
| 立题一句话 + 日期期号 | `cover` | ✅ |
| 头条：序号 + 标题 + 两三行摘要 | `headline` | ✅ |
| 后面几条快讯 | `list` | ✅ |
| 一个要吓人一跳的数字 | `stat` | ✅ |
| 官方 / 受访者引述 | `quote` | ✅ |
| 收尾 + 下期预告 | `closing` | ✅ |

- **固定家具**：报头（栏目名）、期号 + 日期、进度分段、页脚来源；
- **主题方向**：高对比中性色 ↔ 深色资讯感；
- **判断**：现有版式基本覆盖，**差异主要落在主题与家具上**，不需要造新版式。

### 产品介绍 / 品牌宣传

| 信息形态 | 建议版式 | 内核那 6 个版式能覆盖吗 |
| --- | --- | --- |
| 产品名 + 一句话定位 | `cover` | ✅ |
| 单个卖点展开 | `headline` | ✅ |
| 功能清单 | `list` | ✅ |
| 指标数字（性能 / 容量 / 价格） | `stat` | ✅ |
| 用户或媒体评价 | `quote` | ✅ |
| 行动号召 | `closing` | ✅ |
| **前后对比 / 参数表** | — | ❌ **要造新版式** |

- **固定家具**：品牌名（报头位置）、型号 / 版本、价格或档位、页脚官网；
- **主题方向**：品牌色主导 ↔ 深色科技感；
- **判断**：通用部分靠内核；**「对比」「参数表」这类形态内核那 6 个版式装不下**，是新类型包的价值所在。

### 热点解析 → **已沉淀为 `hotspot`**

这份拆解已经走完八步并抽帧验收（记录见 `kits/hotspot/kit.md`），所以下面记的是**实际落地结果**，
而不是起点建议：

| 信息形态 | 版式 | 来源 |
| --- | --- | --- |
| 事件一句话 + 时间 | `cover` | 内核通用 |
| **事件脉络（时间线）** | **`timeline`** | ★ 本次新造 |
| **各方说法对比** | **`stance`** | ★ 本次新造 |
| **多个数字并列** | **`multi-stat`** | ★ 本次新造（内核 `stat` 只能放一个数字） |
| 关键引述 | `quote` | 内核通用 |
| 结论 + 观察点 | `closing` | 内核通用 |
| （次要）头条 / 线索清单 | `headline` / `list` | 内核通用 |

- **固定家具**：栏目名 · **事件当前时间戳** · **消息来源与可信度** · 进度 · 页脚 —— 后两件内核没有；
- **主题方向**：`signal-dark`（冷静数据感）/ `alert-contrast`（高警示头版感）；
- **为什么必需**：三个版式各自对应一种内核装不下的信息形态 —— 时间线（先后关系）、
  并列对照（多方立场）、多数字共用字号（横向比较）。而**两件新家具不需要新增主题维度**
  （只消费已有七个维度），这是「加家具 ≠ 加主题字段」的样本。

> 三个类型的共同结论：**内核负责通用版面，类型包的价值在于那些「现有版式装不下」的信息形态。**
> 如果第 1 步拆完发现全部能落到现有 6 个版式里，那说明**不需要新套件**，改主题 + 扩展家具即可 ——
> 这也是一种正当结论。
>
> **上表里「新闻日报」一行的判断（现有版式基本覆盖）据此仍然成立**：那个类型大概率
> **不需要新套件**。得出这个结论也是框架的正确输出 —— 造不出套件不等于失败，
> 「这次不需要造」同样是第 1 步该给的答案。

## kernel（内核，已实现）

所有视频的基础。它不是一个「组件包」，而是**三层**：

| 层 | 内容 | 契约 |
| --- | --- | --- |
| **主题层** | 4 个主题：`default-dark` / `paper-seal` / `bubble-pop` / `neon-terminal` | `theme-contract.md` |
| **母版层** | 母版引擎（报头 + 页脚 + 内容区预约）+ 6 个通用版式 | `master-contract.md` |
| **组件层** | 19 个契约原语 + 1 个轻量场景脚手架 | `component-contract.md` |

⚠️ **内核不需要 `compose.ts`** —— 它自己就是来源（`components/` 在它这里）。
声明是**类型包**才要写的：它说明自己从谁那儿补入缺的那两层。

另有一个 **`labels.ts`**：五层展品（元素 / 版式 / 家具 / 主题 / 场景）的**中文名**，
只被 `showcase/generate.ps1` 解析、只出现在展示页上（`Title · 主标题`）。
**它不是第四层** —— 不参与出片，所以不进 `Theme` / `LAYOUT_SPECS` / `FurnitureConfig`。
理由与覆盖率校验见 `component-contract.md` §5。

### 主题（换主题不换版式）

| 主题 | 长相 | 改一行就能用 |
| --- | --- | --- |
| `default-dark` | 深色现代：Inter / 微软雅黑，冷蓝强调，圆角 4 | `<MasterFrame theme={getTheme('default-dark')}>` |
| `paper-seal` | 宣纸楷书：KaiTi / FangSong，朱砂强调，方角，宽边距 | 同上换 id |
| `bubble-pop` | 卡通：Comic Sans / 微软雅黑，荧光粉强调，粗胶囊 | 同上换 id |
| `neon-terminal` | 终端：全等宽 + FangSong，霓虹绿强调，1px 直角 | 同上换 id |

**新增主题不动版式一行** —— 判据与实测见 `theme-contract.md`。一个主题一个合成时，
照 `templates/ThemeShowcase.tsx` 的 `THEME_IDS.map(...)` 批量注册。

展示页上每个主题显示成 `paper-seal · 宣纸朱砂` —— 那个中文名住在套件根的 `labels.ts`，
**不在这里重抄一份**（抄一份就是两份真相）。

### 模板

| 模板 | 做什么 |
| --- | --- |
| `Scene` | 单场景脚手架：`Stage` → `SafeArea` → 内容列（不用母版时） |
| `ShowcaseScenes` | **母版演示与主题演示共用的内容**（6 个版式的最坏情况内容 ＋ **8 场** ＋ 家具 hook；`list` 演练三遍：不带主字段 / 带主字段 / 显式节奏对照） |
| `KitShowcase` | 组件层演示 / 验证载体：每个原语都摆了一遍，**18 个场景 1200 帧** |
| `MasterShowcase` | 母版层演示 / 验证载体：默认主题 + **6 个版式**（**8 场** —— `list` 三遍）的抽帧清单 |
| `ThemeShowcase` | 主题层演示 / 验证载体：**同一份内容**换主题跑，用于并排对比 |

### 组件（契约原语）

| 组件 | 做什么 | 关键 props |
| --- | --- | --- |
| `Title` | 主标题，透明度 + 上移入场 | `text` `fontSize` `delayInFrames` `enterDurationInFrames` `align` |
| `Subtitle` | 副标题 / 支撑文字，位移更小 | 同上（默认更缓） |
| `TextReveal` | 逐行揭示，每行装在遮罩里向上推出 | `lines` `staggerInFrames` `lineDurationInFrames` |
| `Emphasis` | 关键词强调：`highlight` 底色块 / `underline` 下划线 / `box` 圈框 | `kind` `color` `delayInFrames` `thickness` |
| `BulletList` | 要点列表，逐条错开入场 | `items` `staggerInFrames` `bulletColor` |
| `Quote` | 引用卡：大引号 + 引文 + 出处 | `text` `attribution` `maxWidth` |
| `SectionHeading` | 章节标题：编号 + 标题 + 生长分隔线 | `index` `title` |
| `ProgressBar` | 进度指示条，填充用 `scale` 生长 | `progress`（由调用方内联算出） |
| `SafeArea` | 安全区容器，按画布缩放 | `insetX` `insetY` `align` |
| `Stage` | 舞台：背景色 + 可选网格 + 可选暗角 | `grid` `vignette` `background` |
| `MediaStage` | 多媒体框：**安全区内放得下的最大 16:9**，放图片 / 视频 / 自绘内容 | `src` `kind` `fit` `label` `labelPlacement` |
| `MediaCard` | 迷你多媒体框：按 `focus` 长大并移到目标矩形 | `from` `to` `focus` `labelPlacement` |
| `ScrollArea` | 滚动区：裁切视口 + 按 `scroll` 平移内容（视频里没有「滚动」这个动作）；`onMeasured` 交出量到的 `{viewport, content}`，锚点算式用 `anchorScroll` | `scroll` `header` `rail` `onMeasured` |
| `TextTag` | 文字标签：一小段文字装在盒子里，四种分量从实底到中性 | `text` `tone` `fontSize` `radius` |
| `RichTextBox` | 富文本框：一段正文里混排加粗 / 高亮 / 等宽，格式写在同一个字符串里 | `text` `box` `fontSize` `align` |
| `BarChart` | 水平条形图：一行一个类别，条长编码数值 | `items` `max` `barHeight` `unit` `decimals` |
| `Panel` | 内容卡：有边界的容器，头 / 身 / 尾三段槽；**框高跟内容走**，讲到别处时可压暗 | `width` `header` `footer` `padding` `shadow` `dim` |
| `Stat` | 大数字：一个数据点（数字 + 单位 + 标签），三段错开入场；单位**按基线**对齐；支持逐位滚动 | `value` `unit` `label` `note` `fontSize` `align` `reserveChars` `rollFrom` `roll` |

`SafeArea` 与 `Stage` 是布局脚手架，故意不做成可交互元素。
**所有原语的颜色与字族都从 `useTheme()` 取**，所以它们跟着主题走。

### 母版版式

`cover` / `headline` / `list` / `stat` / `quote` / `closing`，槽契约见 `master/types.ts` 的 `LAYOUT_SPECS`。

### 依赖

**唯一额外依赖：`@remotion/layout-utils`（官方包，版本随 Remotion）。**

为什么不是「零依赖」：母版的溢出护栏必须**真的测量**。固定时长配变长内容，靠猜字号一定会溢出。这个包提供的 `fitText` / `fitTextOnNLines` 是唯一可靠的做法。

```bash
npx remotion add @remotion/layout-utils
```

### 渲染配置档

纯 DOM，无 WebGL、无外部素材、无字体下载 —— **无特殊渲染要求**。见 `render-profiles.md` 的「纯排版」档。

```bash
npx remotion render <comp-id> out/draft.mp4 --scale=0.5 --crf=28 --jpeg-quality=70
```

### 已知限制

| 限制 | 说明与对策 |
| --- | --- |
| `TextReveal` / `BulletList` 用 `.map()` 渲染，行的 `name` 由索引算出 | Studio 仍可选中，但回写不如硬编码名字稳定。要最大保真度就在调用处逐行摆多个组件 |
| 主题值与原语的字号默认值在 Studio 里是计算值 / 内联常量 | 有意为之 —— 品牌色与字体族不该逐处不同；原语字号要跟随主题就显式传 `theme.type.*` |
| 字体族必须点名目标环境里真实存在的字 | 只写装不上的字体名时，Chromium 会按字重逐段回退 —— 同帧混排宋体 + 黑体，护栏量到的宽度也不是渲染字体的宽度 |
| 暗角会压暗边角，而报头 / 页脚正好在边角 | 次要文字色（`muted` / `furniture`）偏暗的主题必须把暗角收浅，或把这两个色调亮（`neon-terminal` 抽帧后就是这么修的） |
