# 套件展示页设计

范围：`remotion-kits/showcase`，以及技能入口中与展示页有关的使用说明。本文描述**设计与边界**；实施过程中的证据、分支与读数在 git 历史里。

## 1. 目标与边界

展示页是套件的能力目录与交互演示。用户用它找到能力，观察真实效果，更换内容与实例参数，并确认能力由谁维护、当前展示读自哪里。

展示页不持有作品的内容、分镜、场景顺序和时序；不建立「期」实体；不成为另一个 Studio 编辑器。预览控制临时生效，不保存工程，不自动应用更新器，也不把项目的创作改动回填母版。

页面草图只定义信息结构和交互方向。正式页面挂载真实套件组件、已有夹具和新增的展示专用夹具，不能使用草图中的 HTML 模拟画面代替真实渲染。

## 2. 页面结构

**主入口按系统结构组织，类别在页面内部使用** —— 「全部 / 内核 / 类型包」那样的对称筛选会掩盖「只有一个内核、可以有多个类型包」这个事实。侧栏不设「按职责进入」标签；展示固定读取技能母版，顶部不提供来源选择。

| 页面或区域 | 职责 |
| --- | --- |
| 系统总览 | 内核入口、类型包选择入口、组合关系与同步状态；下半区不显示元素分类 |
| 通用内核 | 按实际元素类型分节展示完整自有目录；侧栏标签定位到对应分组和真实试验 |
| 侧栏类型包选择 | 默认折叠；展开后列出实际类型包，选中后进入详情并自动收起；不设目录主页 |
| 类型包详情 | 整体演示、自有目录、组合与依赖分别呈现；类别按包的实际内容出现 |
| 全局搜索 | 跨包查找，结果按真实维护归属分组；点击进入对应能力 |
| 工作台与对照 | 进入能力后的试验工具；保留归属、类型包组合情境与返回路径 |
| 顶部同步 | 母版的构建状态与诊断；页面固定读取母版 |

分类、维护归属和数据来源分别表达。类型包的目录仅取 owned；refs 与 inherited 服务真实组合及依赖说明。通过依赖链接试用内核组件时，可以应用该包的实际主题，但组件的 owner 仍是内核。

侧栏上半区是系统总览、通用内核和「类型包」折叠菜单：点菜单只展开选择列表，不改变主内容；选中类型包进入详情并收起，键盘焦点回到折叠按钮；总览的「选择类型包」按钮展开同一列表。下半区只在内核或类型包情境中显示当前归属的 owned 标签，总览与全局搜索不显示分类。标签与主内容类别标题旁不显示数量，整体摘要仍保留。点标签定位到完整目录中的对应分组（不过滤成单类页面），高亮跟随实际滚动。`category` 深链接是页内书签；旧能力分区链接迁移到对应元素类别；未知或已删除的类型包链接返回系统总览。

顶部工具区占用实际高度，其下剩余视口分给侧栏与主区域。两区各自滚动，滚到边界不连带外层；导航切换重置主区域滚动，参数和帧变化不重置。窄屏将两区上下排列并保留独立滚动，分类仍可达。

侧栏滚动条采用透明轨道、8px 圆角滑块，常态和悬停颜色从当前主题派生；明暗主题与系统高对比模式各自适配。工作台切换只保留工作台 / 对照；返回完整目录由内容区的返回入口承担。

唯一内核由展示配置 library.json 的 kernel 字段声明，或通过 -Kernel 覆盖；其他已发现套件目录归类型包。角色不根据目录名字或 compose 是否存在猜测。配置指向不存在目录时拒绝构建；内核反向依赖类型包时产生诊断。

内核的构件与机制、组合示例分开计数；类型包的版式数和场景数分开计数。整体演示表达能力，具体作品仍可自由构图。

### 2.1 页面材质

展示界面采用 macOS 毛玻璃方向：默认浅色，雾蓝、淡紫和青色静态背景；顶部、侧栏、总览卡片、实例试验和同步弹窗使用半透明表面与背景模糊。圆角、细边框和轻阴影统一控件。浅色使用蓝色选中态；暗色使用灰黑背景、中性灰玻璃表面、浅灰文字与银白选中态。使用本机系统字体，不新增字体或 UI 库依赖。

材质集中在 `gallery/glass-styles.ts`，通过页面级变量切换明暗。目录卡片不逐个叠加模糊，降低大量展品时的合成开销；视频画布不应用模糊，真实组件仍使用自己的套件主题。保持侧栏和主区域独立滚动、实例试验高度限制和进度行为。

所有宽度下页面直接铺满视口，取消外围桌面背景、窗口外边距、边框、圆角和阴影；内部毛玻璃表面保留。窄屏保持上下排列。浏览器不支持背景模糊或用户启用减少透明效果时使用实色表面；减少动态效果和系统高对比模式沿用对应适配。键盘焦点保持可见。

## 3. 来源与运行环境分离

保留 `generate.ps1` 作为 PowerShell 入口。`-Project` 只提供已安装的 React、Remotion、TypeScript、esbuild 与渲染工具链。官方目录不再依赖这个项目的 `src/Root.tsx` 和生产合成注册。

正式生成入口固定读取当前技能的 `kits/`。启动时只借用指定工程的依赖，不发现工程副本、枚举视频目录或提供运行时来源切换。状态和同步详情保留母版路径用于排查。内部验证通过 `--fixture-source` 使用隔离母版夹具，不能由页面切换。

公开入口：

```powershell
# 母版的一次构建；Project 只借用依赖
pwsh -File showcase/generate.ps1 -Project <工程绝对路径>

# 来源发现与校验 / 已发布页面是否跟得上源文件
pwsh -File showcase/generate.ps1 -Project <工程> -DiscoverOnly
pwsh -File showcase/generate.ps1 -Project <工程> -CheckFresh

# 开发时监听并服务页面
pwsh -File showcase/generate.ps1 -Project <工程> -Watch -Port 18499

```

`-Suite` 指定初始打开的内核或类型包，不裁掉完整目录；显式静帧可只抽取这个包的 refs 范围。保留离线双击入口；持续刷新使用本地 HTTP 服务。监听是开发命令的进程生命周期，不创建后台定时自动化。

## 4. 数据模型

schemaVersion 3 的 library 明确唯一 kernel、typePacks 集合与 initialSuite。生成清单包含 `schemaVersion`、`buildId`、`generatedAt`、来源、运行环境、`sourceDigest`、诊断、套件、唯一资产和套件中的引用。

资产的公共字段：`id`、`kind`、`owner`、`name`、`label`、`purpose`、`sourcePath`、`demoIds`。标识由来源归属、类别、局部名称构成。组合引用只记录资产 id 与补入关系，不复制资产对象；它不决定自有目录归属。

演示包含独立 id、名称、所属资产、预览帧与总时长、尺寸以及可用控制。演示内容和控制放展示模块中；它们不改变运行时 Props 契约。

页面直接 import 活的 `COMPONENT_SPECS`、`THEME_IDS/getTheme`、`SKIN_IDS/resolveSkin`、夹具组件及组合声明。JSON 清单是生成缓存，负责检索、归属与诊断；不成为另一份人工登记表。

## 5. 发现与校验

发现由文件系统与已有注册共同完成。

- 原语读取 `COMPONENT_SPECS`，直接挂载其 Demo。
- 主题、皮读取实际注册并校验文件与注册对应关系。
- 版式读取 `LAYOUT_SPECS` 与 `SHOWCASE_LAYOUTS`；从 TS AST 读取夹具的 Sequence 时序与 JSX 内容。唯一版式与重复场景分别记录。
- 母版、家具来自实际目录、导出与 `FurnitureConfig`；真实预览挂载对应 MasterFrame 和夹具。
- 动效从公开导出发现；为已存在的公共计算提供展示适配器。没有演示适配器的新动效仍进入目录，并明确提示缺少演示。
- `compose.ts` 按声明顺序、逐层补缺，只补原语层与组件演示层。来源循环、不存在路径、登记无消费者、声明缺失均产生定位明确的诊断。

公开 Props 校验使用 TypeScript 编译器的实际导出组件类型，支持命名变化、交叉类型与联合类型。不再要求源码必须写成 `type Props = {...}` 才能被识别。声明里的 prop 必须存在；真实 prop 未出现在展示说明中单独报覆盖提示。

不复制母版几何公式。完整画面通过真实母版渲染；边界显示优先读取真实容器的测量结果。静态骨架可说明槽契约，不宣称它复现了完整空间分配。

## 6. 代表性演示

已有原语 Demo、组件层夹具、母版与主题夹具继续可见。

新增展示适配器优先覆盖：

1. Flow：等分 / 比例 / `[1, 'content']`；父级高度、长短内容、通用 JSX 子项。
2. Panel 与皮：两张实际皮、主题切换、实例圆角覆盖；展示实际优先关系。
3. ScrollArea：长短内容、显式滚动与锚点对齐；尺寸由真实组件量测。
4. 动效：帧、起点、时长、位移的临时对照；调用真实 `enterFade` / `fadeUp`。
5. 自由组合：使用原语与普通 JSX 组合内容，证明目录不是封闭构图语言。

新资产自动被发现并重建，不代表系统会自动创作有意义的夹具。新增公开行为时，维护者提供或复用能够表现它的 Demo；缺夹具时目录提示这一事实。

右侧只显示所选演示真正支持的控制。调用示意来自该演示适配器，不把其他组件的参数放在无效面板中。

## 7. 构建与发布

管线：来源快照与发现 → 校验 → 生成独立 entry → TypeScript 检查 → esbuild 浏览器 IIFE → 写候选产物 → 复核来源摘要 → 发布。

警告表示结构不一致，应阻止发布；覆盖提示表示未验证到的分支，页面保留说明。类型检查或构建失败不能只添加 warning 后继续替换页面。

每次成功结果写进 `dist/builds/<buildId>/`，包含 bundle 与 manifest；bundle 内含当前清单与静态资源。最后原子替换根 `index.html`，它指向同一版本的 bundle。失败保留先前入口，旧打开页面仍可加载其版本资源。

源摘要覆盖选中的来源树、未被 import 的新增文件、展示源码与依赖版本。检测同一构建过程中来源又变化时，不发布错误标注的新结果，重新排队。

`-CheckFresh` 对比当前摘要与根入口对应版本清单，不比较日期猜测新旧。返回非零表示未构建、过期或来源不一致。离线页显示构建时间和来源；实时新鲜状态由服务给出。

静态图只在显式要求时生成，缓存属于具体构建版本，不能按「文件已经存在」跳过而沿用旧图。主交互默认仍是真实渲染。

## 8. 监听与刷新

监听来源树与展示代码，包含修改、增加、删除和重命名；不只依赖 esbuild 已知的 import 图。扫描来源摘要作为补充，避免文件系统事件丢失导致静默过期。

变更短暂合并；同一时间只构建一轮。每轮先复核摘要，原字节保存与重复通知不生成新版本；期间再次变化保留脏标记，完成后复核当前摘要并继续处理。失败只记录本轮尝试的摘要，不能把期间的新内容当成已经处理。源码错误时展示失败状态并等待下一次变更；不能退出监听或发布半成品。

本地服务只绑定 loopback。服务提供当前成功页面和状态端点。客户端观察 buildId：构建成功才刷新；构建失败显示未同步提示并保留已有画面。刷新前保留选择、主题、视图、播放位置与合法的临时控制；资产消失时回到目录并明确提示。

状态面板显示当前来源、最后成功构建、待处理变化与错误。产品页面只放帮助用户判断结果的信息，内部栈信息放可展开诊断。

## 9. 文件职责

| 文件 | 职责 |
| --- | --- |
| `generate.ps1` | 兼容原命令习惯，解析参数并启动 Node 管线 |
| Node 构建模块 | 来源摘要、发现、类型校验、entry、构建、版本发布、新鲜度检查 |
| 本地服务模块 | 静态资源、状态、监听与串行重建 |
| `gallery/*` | 能力目录、演示适配器、真实 Remotion 舞台、交互状态与样式 |
| `verify.mjs` / 管线验证 | 浏览器交互与构建失败、文件新增删除、新鲜度等集成验证 |
| `README.md` | 展示页用法、扩展演示方式与已知边界 |

技能入口只留触发条件、构建 / 监听 / 新鲜度命令与 README 指针，不复制设计细节。母版与 Video 仓库镜像同步；项目 kit 副本与更新器不在本次写入范围。

## 10. 验收

- 母版构建不需要项目 `Root.tsx`，仅借用依赖。
- 使用真实套件组件和真实夹具；唯一内核、已发现类型包及实际主题可预览，补入层保留真实归属。
- 新资产被发现，删除或重命名不留下假展品；版式数与场景数可分别查验。
- Flow 的内容与高度、皮的实例覆盖、ScrollArea 与动效跨帧均通过真实浏览器行为检查与看图。
- 注册或 Props 不一致、类型错误、构建错误阻止发布，旧页面与旧 buildId 保持。
- 文件变化触发重建；成功刷新，失败提示；未 import 的新增文件也参与摘要与发现。
- `-CheckFresh` 对未构建、过期、成功构建分别给出正确退出码。
- 页面支持职责导航、页内分类、按归属分组的搜索、来源识别、工作台与对照；小窗口无横向页面溢出，键盘能操作，减少动态效果设置生效。
- 技能母版与仓库镜像逐文件相同；不修改工程副本，不触发更新器。
